Section 2

Environment Variables & API Keys

Location: rpa-intel-os/.env.local — this file is excluded from Git via .gitignore. Never commit it.

Required Variables

ANTHROPIC_API_KEY=sk-ant-api03-...      # Your Anthropic API key
ANTHROPIC_MODEL=claude-sonnet-4-5       # Model version

How to Rotate the API Key

1
Go to https://console.anthropic.com → API Keys → Create new key
2
Open .env.local in any text editor (Notepad works) and replace the value of ANTHROPIC_API_KEY
3
Restart the dev server: press Ctrl+C in your terminal, then run npm run dev again
4
Verify: click Refresh (Claude) on any module page. If highlights appear, the key is working.
Security rules: Never paste API keys into GitHub issues, Slack messages, or shared documents. Rotate keys every 90 days. The .env.local file must never be committed to Git.
Section 3

How to Add a New Country

All country data lives in: lib/mockData.ts

1
Add the country entry to the allCountryAnalyses array in lib/mockData.ts:
{
  country: "Morocco",
  continent: "Sub-Saharan Africa",  // or "Latin America" — must match exactly
  policy: {
    score: 3.2,
    justification: "Describe the policy environment in 1–2 sentences..."
  },
  capital: {
    score: 3.8,
    justification: "Describe capital flow maturity..."
  },
  infrastructure: {
    score: 3.0,
    justification: "Describe the intermediary ecosystem..."
  },
  talent: {
    score: 3.5,
    justification: "Describe local talent availability..."
  },
  fetchedAt: "2026-04-30T00:00:00Z",
}
2
Add the flag emoji to the FLAG_MAP constant in components/modules/ExpansionScreener.tsx:
Morocco: '🇲🇦',
3
Add CSO metrics to lib/moduleSeedData.ts (optional — the platform uses sensible defaults if omitted).
4
Add a regulatory profile to lib/regulatoryData.ts following the existing country pattern.
5
Test: Run npm run dev, navigate to Expansion Screener, and confirm the new country card appears. Click through to Feasibility Scorecard to confirm all four pillars populate.
Continent values must match exactly: Only "Sub-Saharan Africa" and "Latin America" are currently supported as continent groupings. Any other value will cause the country to be invisible in the Expansion Screener map.
Tip: The composite score and model recommendation are computed automatically from the four pillar scores — you do not need to calculate or hardcode them.
Section 4

How to Update Scoring Data

Scenario: A policy change has occurred (e.g., new NGO law enacted in Brazil)

1
Open lib/mockData.ts and find the relevant country entry. Update the pillar score and justification:
policy: {
  score: 3.8,   // was 3.5 — updated after CL 227/2026 partial state adoption
  justification: "9 of 26 states now exempt CSO donations under CL 227/2026 (Apr 2026). Federal framework unchanged."
},
2
The composite score recalculates automatically. No script is needed — lib/scoring.ts recomputes it in real time on every page load.
3
Update the fetchedAt timestamp so users can see when the data was last reviewed:
fetchedAt: "2026-04-30T00:00:00Z"
4
Save the file. In dev mode, Next.js hot-reloads automatically. For production:
npm run build
npm run start
Section 5

How to Modify Indicator Weights

Warning: Changing weights alters composite scores for all 21 countries simultaneously. Always document the change with a rationale and date.

Location: lib/scoring.ts

Current Weights

export function computeComposite(
  policy: number,
  capital: number,
  infrastructure: number,
  talent: number
): number {
  return (policy * 0.25) + (capital * 0.30) + (infrastructure * 0.25) + (talent * 0.20);
}

Example — Increasing Capital Weight Post-USAID Withdrawal

export function computeComposite(
  policy: number,
  capital: number,
  infrastructure: number,
  talent: number
): number {
  // v1.1 — 2026-04-30: Increased capital weight from 0.30 to 0.35
  // Rationale: USAID withdrawal makes donor diversity the highest-priority variable
  return (policy * 0.20) + (capital * 0.35) + (infrastructure * 0.25) + (talent * 0.20);
}

Rules

  • Weights must sum to exactly 1.00
  • Update the weight labels shown on pillar cards in components/modules/FeasibilityScorecard.tsx (search for "25% weight" etc.)
  • Add a changelog comment in the code explaining the rationale
  • Rebuild for production: npm run build
Section 6

How to Update the Model Matrix

Location: components/modules/ModelMatrix.tsx — find the STATIC constant near the top of the file.

The three expansion models (New Build, Hybrid, Local Partner) are each defined with these fields:

FieldTypeDescription
coststringEstimated setup cost range (e.g. "$800K–$2.5M")
timelinestringMonths to operational readiness
keyRisksstringPrimary regulatory and operational risks
rpaIntensitystringRPA oversight level required
bestFitstringIdeal country profile for this model
precedentstringExample organisations that have used this model
riskLevelnumber (0–5)Execution risk score — drives the risk meter bar

Example — Updating New Build Cost Range

"New Build": {
  cost: "$3.0M–$7.5M+ (legal entity, licenses, systems, launch team)",  // updated
  riskLevel: 4.5,  // increased after observed market entry costs
  // ... all other fields remain unchanged
},

To add a fourth model, add a new entry to both the MODELS array (line ~7) and the STATIC object, following the same structure as the existing three.

Troubleshooting Common Issues

IssueLikely CauseFix
Score shows 0 or NaNMissing or null pillar score in mockData.tsCheck all 4 pillar scores are numbers, not undefined
New country not in Expansion ScreenerWrong continent stringMust exactly match "Sub-Saharan Africa" or "Latin America"
Refresh (Claude) returns errorInvalid or expired ANTHROPIC_API_KEYRotate key in .env.local, restart server
Refresh (Claude) returns "Incomplete response"Claude returned partial JSONEdit the prompt for that action in app/api/claude/route.ts — add stricter JSON format instructions
Map iframe blank for new countrygetCountryMapEmbed() missing entryAdd country to lib/countryGeo.ts
App won't start — port in useAnother Next.js process already runningRun: taskkill /F /IM node.exe (Windows) then retry
Build fails — TypeScript errorIncorrect type in new country entryEnsure continent matches the union type and all scores are number
Report-Ready Analysis card missing on a pageModuleClaudeRefresh not placed correctlyAdd <ModuleClaudeRefresh moduleKey="..." country={activeCountry} /> immediately after the description <div>
PowerShell blocks npm run devExecution policy restrictionUse Command Prompt (cmd) instead of PowerShell

Still Stuck?

  • Check .next/dev/logs/next-development.log for detailed Next.js error traces
  • Run npm run build for a full TypeScript compile check — it shows all errors with line numbers
  • Hard refresh the browser: Ctrl+Shift+R (clears Next.js client cache)
